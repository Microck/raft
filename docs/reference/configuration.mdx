# Configuration reference

The Raft controller CLI reads host inventory and image mappings from `~/.config/raft/incus.json`.

## File location and security

```text
~/.config/raft/incus.json
```

Ensure the configuration file is accessible only by your user account:

```sh title="CONTROLLER: Set strict file permissions"
chmod 600 ~/.config/raft/incus.json
```

## Schema format

The configuration file maps location names to host definition objects:

```json title="Example ~/.config/raft/incus.json"
{
  "lab": {
    "ssh": "ubuntu@192.0.2.10",
    "image": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "note": "Preferred for builds"
  },
  "remote-builder": {
    "ssh": "builder.example.com",
    "image": ""
  }
}
```

### Location keys

- **Naming format**: Matches `^[a-zA-Z0-9][a-zA-Z0-9_-]*$`. Starts with an alphanumeric character and contains ASCII letters, digits, underscores, or hyphens.
- **Default location**: The first location listed is the default for `raft new`. `raft list`, `raft capacity`, `raft gc`, and `raft prune` accept `--location` filters. Without a filter they check all configured hosts; `raft doctor` always checks all configured hosts.

### Host entry fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `ssh` | `string` | Yes | Non-empty SSH connection string (IP, `user@host`, or SSH host alias from `~/.ssh/config`). |
| `image` | `string` | For `raft new` only | Full 64-character hexadecimal SHA-256 fingerprint (`^[a-f0-9]{64}$`). An empty string `""` is allowed during initial host provisioning. |
| `note` | `string` | No | Operator guidance for choosing this location, such as `Preferred for builds` or `Do not use for Docker`. Raft shows notes but never enforces them. |

Set or clear notes with `raft note` instead of editing the file by hand:

```sh title="CONTROLLER: Record location guidance"
raft note lab "Preferred for builds"
raft note spare "Do not use for Docker builds"
raft locations
raft note spare --clear
```

`raft note` rewrites the file with two-space indentation, keeps location order and
mode `0600`. `raft locations`, `raft capacity` and `raft new` show the note.

<Callout type="warn" title="Replace placeholder image fingerprint">
The `image` field requires the full 64-character hash for `raft new`; aliases such as `raft-dev` are rejected. Replace the example hash with the actual imported image fingerprint for that host.

ARM64 and AMD64 images produce different fingerprints; do not reuse an ARM64 hash on an AMD64 host.
</Callout>

## Defaults for new

`~/.config/raft/config.json` is optional. It sets defaults for `raft new` on this
controller and is separate from the location inventory:

```json title="Example ~/.config/raft/config.json"
{
  "defaults": {
    "location": "lab",
    "ttl": 3600,
    "cpu": 2,
    "memory": "4GiB",
    "disk": "20GiB",
    "disposable": true
  }
}
```

| Key | Accepted values | Built-in default |
| :--- | :--- | :--- |
| `location` | A configured location name | First configured location |
| `ttl` | `60` to `2592000` seconds | `600` |
| `cpu` | A positive whole number | `1` |
| `memory` | Whole GiB, e.g. `16GiB` | `2GiB` |
| `disk` | Whole GiB for an own box disk, or `shared` | `shared` |
| `disposable` | `true` or `false` | `false` (persistent) |

Explicit flags win over these values; `--persistent` overrides `disposable`.
`cpu`, `memory` and `disk` size only boxes created from the image: `new --from`
and `fork` keep the source's size unless a flag overrides it. `disposable`
applies to `new` and `new --from`, never to `fork`. A `disk` default needs the `raft-disks` pool on the target
host, like `--disk`. Unknown keys and invalid values make
`raft new` fail with the file path and key. Edit the file with
`raft config set KEY VALUE` and `raft config unset KEY`, and inspect it with
`raft config`. Required box note fields and stopped-box retention are host
policies, not part of this file; see
[Defaults and host policies](../guides/config-policy.mdx).

## SSH configuration and connection behavior

Primary remote commands (`raft ssh`, `upload`, `download`, and control commands) run OpenSSH with `BatchMode=yes` and `-o ConnectTimeout=10` to fail fast on unreachable hosts. The timeout applies to initial connection establishment, not session or transfer duration.

Other operations, recovery routines, and tunnels use standard SSH defaults without an explicit timeout flag.

Configure host connections in `~/.ssh/config` for batch authentication:

```text title="~/.ssh/config"
Host lab-host
    HostName 192.0.2.10
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

Verify passwordless batch SSH before running Raft commands:

```sh title="CONTROLLER: Verify passwordless batch connection"
ssh -o BatchMode=yes lab-host "echo SSH connection verified"
```
