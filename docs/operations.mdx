# Installation and host setup

Set up a dedicated Ubuntu host, install the Raft CLI, provision Incus, acquire a workspace image, and verify readiness.

Review prerequisites in [System requirements](./requirements.mdx) before starting.

<Steps>

<Step>

### Install prerequisites on the workspace host

Connect to your host over SSH, verify its host key fingerprint, and install baseline packages:

```sh title="HOST: Install baseline system packages"
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  ca-certificates curl gnupg python3 openssh-server iptables btrfs-progs
```

Verify passwordless `sudo` on the host:

```sh title="HOST: Verify passwordless sudo"
sudo -n true && echo "Passwordless sudo is functional"
```

</Step>

<Step>

### Install the CLI and obtain deployment scripts

On your Linux controller with Python 3.11.8+, install the published CLI:

```sh title="CONTROLLER: Install published CLI"
npm install -g @microck/raft@0.2.0
raft --version
```

Installation does not configure hosts or download images. Clone the matching
release to obtain the deployment scripts and example configuration:

```sh title="CONTROLLER: Obtain deployment scripts"
git clone --branch v0.2.0 https://github.com/Microck/raft.git raft
cd raft
```

Alternatively, install from that checkout using `uv` instead of npm:

```sh title="CONTROLLER: Clone repository and install CLI"
uv sync --locked
uv tool install --editable .
```

For the `uv` installation, add `~/.local/bin` to `PATH` and verify the CLI:

```sh title="CONTROLLER: Verify CLI installation"
export PATH="$HOME/.local/bin:$PATH"
raft --help
```

</Step>

<Step>

### Configure host inventory on the controller

The controller reads host definitions from `~/.config/raft/incus.json`. Initialize the configuration directory and template:

```sh title="CONTROLLER: Initialize configuration file"
mkdir -p ~/.config/raft
cp docs/incus.example.json ~/.config/raft/incus.json
chmod 600 ~/.config/raft/incus.json
```

Verify interactive SSH to establish known host keys:

```sh title="CONTROLLER: Verify host SSH access"
ssh user@host-address "echo Host SSH connected successfully"
ssh -o BatchMode=yes user@host-address "echo Batch SSH functional"
```

Edit `~/.config/raft/incus.json`. Set the `ssh` target. Leave `image` empty during initial setup:

```json title="CONTROLLER: ~/.config/raft/incus.json"
{
  "lab": {
    "ssh": "user@host-address",
    "image": ""
  }
}
```

Location names use letters, digits, underscores, or hyphens. The first configured location is the default for `raft new`.

</Step>

<Step>

### Provision the dedicated host

Run the automated host deployer from your controller:

```sh title="CONTROLLER: Provision host infrastructure"
python3 deploy/deploy.py --location lab
```

<details>
<summary>Infrastructure created by the deployer</summary>

The deployer runs over SSH and configures the host:
1. Installs Incus 6.0 LTS and nftables packages.
2. Creates the isolated `raft` Incus project.
3. Creates a 60 GiB Btrfs storage pool (`raft-data`).
4. Creates private bridge interface `rfbr0` (`10.232.0.1/24`) with NAT.
5. Configures nftables bridge filters to block inter-workspace traffic and restrict host access.
6. Installs and enables `raft-network.service` and `raft-expire.timer` units.

</details>

</Step>

<Step>

### Acquire a native workspace image

Workspaces require an unprivileged Debian 13 development image matching the host architecture:

<Tabs items={["Download release image", "Build from source"]}>

<Tab value="Download release image">

Download the release archive, checksum, and manifest from [Raft releases](https://github.com/Microck/raft/releases). These examples pin `v0.2.0`, matching the CLI and deployment checkout above. The `sha256sum` check gates import so corrupted archives are rejected:

<Tabs items={["ARM64", "AMD64"]}>

<Tab value="ARM64">

```sh title="HOST (ARM64): Download, verify, and import release image"
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/raft-dev-arm64.tar.gz
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/SHA256SUMS
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/manifest-arm64.json

sha256sum --ignore-missing -c SHA256SUMS && \
  sudo incus --project raft image import ./raft-dev-arm64.tar.gz --alias raft-dev
```

</Tab>

<Tab value="AMD64">

```sh title="HOST (AMD64): Download, verify, and import release image"
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/raft-dev-amd64.tar.gz
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/SHA256SUMS
curl -fsSL -O https://github.com/Microck/raft/releases/download/v0.2.0/manifest-amd64.json

sha256sum --ignore-missing -c SHA256SUMS && \
  sudo incus --project raft image import ./raft-dev-amd64.tar.gz --alias raft-dev
```

</Tab>

</Tabs>

</Tab>

<Tab value="Build from source">

Run the build script from your controller. It pulls Debian 13 to the host, installs development runtimes and Docker, and publishes alias `raft-dev`:

```sh title="CONTROLLER: Build native development image"
python3 deploy/build-image.py --location lab
```

<Callout type="warn" title="Do not pin the base image fingerprint">
During the build, the script downloads an upstream Debian base image and logs its intermediate fingerprint. Do not copy that initial fingerprint; retrieve and pin the final `raft-dev` image fingerprint in the next step.
</Callout>

</Tab>

</Tabs>

</Step>

<Step>

### Retrieve and pin the image fingerprint

Query the published `raft-dev` image on the host:

```sh title="HOST: Retrieve published image fingerprint"
sudo incus --project raft image list raft-dev --format json | python3 -c '
import json, sys
data = json.load(sys.stdin)
print(next(img["fingerprint"] for img in data if any(a.get("name") == "raft-dev" for a in img.get("aliases", []))))
'
```

Copy the 64-character hex output into `image` in `~/.config/raft/incus.json` on the controller:

```json title="CONTROLLER: ~/.config/raft/incus.json"
{
  "lab": {
    "ssh": "user@host-address",
    "image": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

Replace the example string with your actual fingerprint. Raft requires this immutable fingerprint to prevent unexpected image mutations when creating workspaces.

</Step>

<Step>

### Check host status with doctor

Run `raft doctor` on your controller to inspect host readiness:

```sh title="CONTROLLER: Run doctor diagnostics"
raft doctor
```

Check that Incus, the network service, and the expiration timer are active. For the full report contents, see [Controller diagnostics](./guides/troubleshooting.mdx#controller-diagnostics).

</Step>

</Steps>
