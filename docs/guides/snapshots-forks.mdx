# Snapshots and forks

Raft captures filesystem snapshots, rolls back changes, and clones workspaces on the same host.

## Target workspace handle

Commands in this guide require a stopped workspace:

```sh title="CONTROLLER: Select and stop target workspace"
raft list
box="lab:rf-a1b2c3d4e5f60718"  # Replace with your actual workspace handle
raft stop "$box"
```

## Stopped-source requirement

<Callout type="warn" title="Workspace must be stopped">
Creating a snapshot, restoring from a snapshot, or forking requires a stopped container. Operations run under host lock `/run/lock/raft-incus.lock` to prevent concurrent disk modification.
</Callout>

## Creating snapshots

Take a point-in-time snapshot of the stopped workspace filesystem:

```sh title="CONTROLLER: Create a named snapshot"
raft snapshot "$box" pre-upgrade
```

Snapshot names must use letters, digits, underscores, or hyphens up to 64 characters.

## Listing snapshots

View existing snapshots for a workspace:

```sh title="CONTROLLER: List existing snapshots"
raft snapshots "$box"
```

The command prints snapshot names and creation timestamps from Incus metadata.

## Restoring from a snapshot

Roll back a stopped workspace to a previously recorded snapshot:

```sh title="CONTROLLER: Restore snapshot"
raft restore "$box" pre-upgrade
```

<Callout type="info" title="Configuration preservation during restore">
`raft restore` executes Incus snapshot restore with `--diskonly`. It rolls back filesystem blocks while preserving container configuration, CPU and memory limits, and the `eth0` network MAC address.
</Callout>

Resume the workspace with a renewed lifetime:

```sh title="CONTROLLER: Resume restored workspace"
raft resume "$box" --ttl 600
```

## Forking a workspace

Forking creates an independent clone on the same host:

```sh title="CONTROLLER: Fork workspace into a new clone"
copy=$(raft fork "$box" --ttl 600)
echo "Created fork: $copy"
```

### Characteristics of forked workspaces

- **Instance-only copy**: Uses Incus `--instance-only`. Filesystem data, installed packages, and `/workspace` files are copied; source snapshots are not inherited.
- **Immediate start**: `raft fork` launches the new container immediately with the specified TTL while the source remains stopped.
- **Fresh network identity**: The fork receives a new container name, a fresh MAC address on `rfbr0`, and an independent IP address.
- **Disk**: The fork keeps the source disk. Both kinds fork in seconds as copy-on-write snapshots: a shared-pool source within the shared 60 GiB Btrfs pool, an own-disk source as a thin snapshot that reserves its full size in `raft-disks`.

Destroy the clone when finished to release capacity:

```sh title="CONTROLLER: Destroy forked workspace"
raft destroy "$copy"
```

## Starting from a prepared snapshot

```sh
copy=$(raft new --from "$box/pre-upgrade" --ttl 600)
```

The source box can be running because Raft copies the saved snapshot. The new box stays on the same host, keeps the snapshot's CPU, RAM and disk unless `--cpu`, `--memory` or `--disk` overrides them, and has a fresh network identity. Copies are copy-on-write snapshots, so starting many boxes from one prepared snapshot is fast; on own disks each copy still reserves its full size. Filesystem secrets are copied too.

Add `--disk SIZE` to copy the snapshot onto an own disk of a new size, for example to give a full box more room:

```sh
bigger=$(raft new --from "$box/pre-upgrade" --disk 40GiB --ttl 600)
```

Remove a snapshot you no longer need:

```sh
raft snapshot-delete "$box" pre-upgrade
```

## Choosing clone resources

```sh
copy=$(raft fork "$box" --ttl 600 --cpu 2 --memory 4GiB)
raft resume "$box" --ttl 600 --memory 2GiB
```

Omitted CPU and RAM values keep the source limits; the disk never changes on fork or resume. Forks are persistent by default; add `--disposable` to delete a clone when it stops or expires.
