# Background jobs

Raft allows you to run detached background commands inside workspaces. Detached execution runs commands under the guest systemd init system using transient service units.

## Target workspace handle

Commands in this guide target an existing running workspace. Review [First working box](../first-box.mdx) to launch a new workspace, or select an existing one with `raft list`:

```sh title="CONTROLLER: Select running workspace"
raft list
box="lab:rf-a1b2c3d4e5f60718"  # Replace with your actual workspace handle
```

## Launching detached commands

To start a command in the background, pass the `--detach` flag to `raft exec`, placing the workspace handle first and delimiting the command with `--`:

```sh title="CONTROLLER: Start a detached background job"
job=$(raft exec "$box" --detach -- bash -lc '
echo "Task started at $(date)"
sleep 60
echo "Task finished at $(date)"
')
echo "Started background job: $job"
```

The command returns immediately with a 32-hex systemd unit name prefixed with `rfcmd-` (for example `rfcmd-a1b2c3d4e5f60718293a4b5c6d7e8f90`).

## Checking job status

Use `raft status` to query the underlying systemd unit properties:

```sh title="CONTROLLER: Inspect background job state"
raft status "$box" "$job"
```

The command outputs the unit properties queried from `systemctl show`:
```text
ActiveState=active
SubState=running
ExecMainStatus=0
```

Because Raft runs detached commands with `RemainAfterExit=yes`, completed jobs remain recorded after exiting:
```text
ActiveState=active
SubState=exited
ExecMainStatus=0
```

<Callout type="info" title="Exit status vs CLI return code">
`ExecMainStatus` reports the exit code returned by your command payload inside the guest container. The `raft status` command itself returns exit code 0 whenever the systemd query succeeds. `raft status` queries unit state; it does not report process PIDs or start timestamps.
</Callout>

## Viewing job logs

Use `raft logs` to retrieve standard output and standard error recorded by the guest journal:

```sh title="CONTROLLER: Retrieve job log output"
raft logs "$box" "$job"
```

The command executes `journalctl --no-pager -o cat -u <job>` inside the container, printing existing journal records. It outputs recorded logs without a pager and without streaming or follow mode.

## Cancelling jobs

To terminate a running detached command, use `raft cancel`:

```sh title="CONTROLLER: Terminate background job"
raft cancel "$box" "$job"
```

`raft cancel` calls `systemctl stop <job>`, cleanly terminating processes within the job's systemd control group.

## Extending workspace lifetime

<Callout type="warn" title="No process checkpointing">
Stopping a workspace with `raft stop` or allowing its TTL to expire terminates all running background jobs. Raft does not freeze or checkpoint running process memory.
</Callout>

If a detached job requires additional time to finish, use `raft extend` before the workspace expires:

```sh title="CONTROLLER: Reset workspace expiration"
raft extend "$box" --ttl 1800
```

`raft extend` resets the container expiration deadline to `now + TTL` seconds. It calculates the new deadline from the current host timestamp; it does not append time to the existing deadline.
