# Measure startup on your host

Creation can return a handle before the box accepts commands or Docker is ready. Measure the readiness your workload needs rather than treating CLI return as full startup.

Raft development images are native Debian 13 images for ARM64 and AMD64, not emulation. Images and recovery targets must match host architecture. Get images through [onboarding](./operations.mdx), or use the [upgrade guide](./guides/upgrades.mdx) to build and pin another image.

## Read native startup samples

Five samples per architecture from [native CI on 2026-10-06](https://github.com/Microck/raft/actions/runs/37447415532), using 4-CPU hosts and 1-CPU, 2-GiB boxes with cached images:

| Median | ARM64 | AMD64 |
| --- | ---: | ---: |
| Create returns handle | 0.425 s | 0.659 s |
| Create accepts a command | 0.866 s | 1.375 s |
| Docker ready after create | 2.280 s | 3.035 s |
| Resume accepts a command | 0.951 s | 1.489 s |
| Docker ready after resume | 2.626 s | 3.049 s |
| Desktop ready after its separate start request | 1.115 s | 1.592 s |
| Compressed image | 1.79 GiB | 1.86 GiB |

Read the [ARM64 samples](./benchmarks/arm64-native-ci.json) and [AMD64 samples](./benchmarks/amd64-native-ci.json) for distributions. Hardware and SSH latency differ between runners, so these numbers do not establish an architecture advantage or compare Raft with Boat.

## Measure your own host

Use a dedicated test location with a pinned image and a matching source checkout. The benchmark creates, stops, resumes and destroys its own boxes. It also starts the desktop when requested; do not target a shared or daily-use test channel.

```sh
python3 deploy/benchmark-boot.py --location lab --samples 5 --desktop > boot.json
```

You can request 1 to 20 samples. Each sample measures request-to-return, command readiness and Docker API readiness, then repeats after stop/resume. Desktop timing starts at its separate startup request and waits for HTTP 200 and an RFB greeting. It does not measure remote browser rendering.

Reports include median, minimum, maximum, nearest-rank p95, SSH round trip, image size and guest boot information. With three or five samples, p95 is effectively the maximum, not a stable production percentile.

All controller-visible times include CLI and SSH overhead. They exclude image downloads and host reboots. First use after import or cache eviction can take longer while storage unpacks; hardware, load, packages and services also affect results. A stopped box restores files, not process memory.
